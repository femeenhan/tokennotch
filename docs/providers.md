# 제공자별 정령

2026-09-16 구현. Codex·Claude·Gemini·Grok 각각 정령 하나를 사용하며 화면에는 최대 세 개를 표시한다. 설정 → 함께하기 또는 메뉴 막대 → 정령 표시에서 선택한다. 기본 선택은 기존 Codex 한 개를 유지한다. 모두 숨길 수도 있다.

## 표시와 조작

정령 아래 이름표는 제공자 이름으로 고정한다. 작업 중에는 망치질과 ▶, 확인 요청은 !, 오류는 ×, 세션 종료의 짧은 완료 표현은 ✓를 표시한다. 아직 이벤트를 받지 않았거나 상태를 확인할 수 없으면 ?를 표시한다. 동작 줄이기에서도 기호가 상태를 전달한다. 각 정령의 위치·크기는 따로 저장한다. 전체 표시·전체 화면 숨김·소리·집중 타이머·리마인더는 앱 공통 설정이다.

캐릭터 클릭은 해당 제공자의 요약 말풍선, 우클릭은 관리 메뉴, 드래그는 위치 이동이다. 시각 창은 항상 클릭을 통과시키고, 별도 입력 창이 몸통·머리·불꽃·망치와 작은 여유 영역의 클릭을 받는다. 입력 창 안의 파츠 사이 투명한 틈도 클릭 대상이다. 시각 창 바깥 모서리는 아래 앱으로 통과한다. 한 번에 하나의 말풍선을 열며 다른 정령을 클릭하면 그 제공자의 요약으로 전환한다.

연결과 화면 표시는 독립이다. 정령을 숨겨도 실행 중인 앱은 해당 제공자의 이벤트를 저장한다. 같은 제공자에서 여러 세션을 실행하면 정령 하나가 집계한다. 확인 요청·오류·진행 중 작업은 완료 동작보다 우선한다. 다른 제공자의 이벤트는 이 상태에 영향을 주지 않는다.

## 대시보드

상단 제공자 선택으로 사용량과 도구 기록을 전환한다. 정령 말풍선이나 우클릭 메뉴에서 열면 해당 제공자가 선택된다. Codex의 한도·히트맵·로그 토큰·API 환산 기능을 유지한다. Claude·Gemini·Grok은 실제 수신한 세션 상태와 도구 범주를 표시하며 계정 한도·토큰·환산액은 조회 미지원으로 표시한다. 제공자별 한도를 합산하지 않는다.

실시간 상태와 저장 기록은 구분된다. 재실행한 앱은 이전 활성 세션을 정상 대기로 추정하지 않으며, 기록 화면의 해당 세션은 unknown으로 복원한다. 작업 기록은 이벤트를 받은 범위만 포함한다. 앱 종료 중 훅 이벤트는 복구하지 않는다.

## CLI 연결

설정 → CLI 연결에서 제공자 선택 → 추가할 설정 미리보기 → 연결 설정 설치를 사용한다. 이 구현 작업은 새 제공자의 사용자 설정을 자동으로 설치하지 않는다. 설정이 손상되거나 대상 디렉터리 권한이 안전하지 않으면 변경을 거부한다. 기존 설정은 백업하고 다른 훅은 보존한다. 제거는 현재 앱 경로의 명령과 정확히 일치하는 훅만 제거한다.

| 제공자 | 기본 설정 경로 | 브리지 인자 |
|---|---|---|
| Codex | `$CODEX_HOME/hooks.json` 또는 `~/.codex/hooks.json` | `--codex-hook` |
| Claude Code | `~/.claude/settings.json` | `--claude-hook` |
| Gemini CLI | `~/.gemini/settings.json` | `--gemini-hook` |
| Grok CLI | `~/.grok/hooks/build-spirit.json` | `--grok-hook` |

Codex는 `/hooks`에서 사용자가 직접 신뢰 승인해야 한다. Claude는 설정 파일 변경 감시로 훅이 일반적으로 자동 반영되며, Gemini는 설치 후 세션을 다시 시작해 실제 이벤트 수신을 확인한다. Grok은 CLI와 설정 읽기 방식의 실사용 검증이 남은 실험적 연결이며 `~/.grok` 상위 폴더가 이미 있어야 설치할 수 있다. 공식 문서와 fixture로 구현한 연결이며 설치된 실제 CLI의 전 이벤트 검증을 완료한 것으로 표시하지 않는다. 웹 채팅·데스크톱 앱·IDE 확장은 지원 범위가 아니다.

Claude Code는 앱이 CLI와 훅 설치 상태를 자동으로 감지한다. 설정 → CLI 연결에서 Claude Code 자동 연결을 한 번 켜면 앱 재실행 시 현재 앱 경로의 훅을 확인하고 필요하면 다시 설치한다. 기존 훅은 보존하고 설정 파일을 백업한다. 연결 이후 첫 Claude 작업 이벤트가 오면 빈 표시 슬롯에 Claude 정령을 표시하고 대시보드 제공자를 Claude로 전환한다. 표시 슬롯이 모두 찼으면 사용자가 하나를 숨길 때까지 기존 선택을 유지한다. 스위치를 끄면 현재 앱 경로의 Claude 훅만 제거한다. Claude Code 설정 파일 변경은 일반적으로 실행 중인 CLI에서도 자동 반영되지만 이미 지나간 이벤트는 복구되지 않는다.

Claude/Gemini의 공통 훅에 없는 turn ID는 만들지 않는다. Grok의 promptId와 공식 timestamp는 제공되는 경우 사용한다. 하위 에이전트 입력이 부모 세션 ID를 공유하고 자식 식별자를 가진 경우 부모 상태를 잘못 종료하지 않도록 제외한다. 따라서 자식별 정밀 관측은 미지원이다. PostToolUse는 성공을 보장하지 않으며 명시적 실패 이벤트만 실패로 기록한다.

Grok이 Claude 설정의 훅을 읽는 경우에도 Grok의 별도 입력 형식을 Claude 어댑터에서 거부해 활동을 잘못 분류하지 않는다. 프롬프트·응답·명령·코드·도구 결과는 이벤트에 저장하지 않는다.

## 저장과 검증

SQLite v1에서 v2로 내부 식별자를 이전한다. 제공자와 원본 ID를 함께 사용해 같은 세션·이벤트 ID가 다른 제공자에서 나타나도 충돌하지 않는다. 기존 Codex 기록과 프로젝트 배정을 이전하고 원본 sessionID를 보존한다.

검증은 제공자별 상태/완료 콜백, 중복·최대 세 개 선택, 교차 제공자 ID 충돌, 실제 v1 DB 이전, 제공자별 조회, 네 제공자의 Unix socket 수신, 어댑터 개인정보 제외, 설치 병합/제거/백업, 내장 브리지→앱→저장 통합을 포함한다. 통합 테스트는 임시 소켓·DB를 사용한다. 테스트용 `--providers codex,claude,gemini`는 시작 시 표시 선택만 덮어쓰고 사용자 선택을 저장하지 않는다.

공식 입력 계약: [Claude Code hooks](https://code.claude.com/docs/en/hooks), [Gemini CLI hooks](https://geminicli.com/docs/hooks/reference/), [Grok CLI hooks](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/10-hooks.md).

최종 검증 결과: 코어 155개/21 suite 통과, 다중 정령 1개·브리지 6개·앱 훅 3개·대시보드 1개·계정 한도 1개 통합 테스트 통과, Swift 6 Debug 빌드 성공. 실제 화면에서 Codex→Claude 전환 시 Codex 수치가 숨겨지는 것, 세 개 선택 시 네 번째 선택이 비활성화되는 것, Gemini 숨김→Grok 표시→원래 구성 복원을 확인했다. 기존 프로젝트 문법 검사와 diff 공백 검사도 통과했다. 다른 앱 위 중앙 클릭·드래그와 다중 모니터·잠금·절전의 수동 실기 검증은 여전히 남아 있다.
